# Windows 原生 Claude Code 配置向导 · 预览版

这是一个分步骤的本地配置向导。运行环境是 Windows 原生终端，不需要 WSL、Python、Node.js 或 Conda。

目前属于预览版：已验证核心逻辑，真实新电脑安装、真实线路和真实账号授权仍需验收。此工具帮助配置本地环境，不提供账号不会被限制的保证。

## 开始使用

1. 解压整个 ZIP，不要在压缩软件里直接运行。
2. 双击 **Configure.cmd**，保留打开的终端窗口。
3. 按六个步骤操作，输入 `y` 表示同意，直接回车表示不同意。

| 步骤 | 你需要做什么 |
| --- | --- |
| 1. 环境检查 | 查看已有程序和配置提示；已有认证/代理配置冲突时先处理 |
| 2. 线路导入 | 在代理客户端导入线路提供者给的订阅或配置文件，选择节点并保持连接 |
| 3. 终端网络 | 使用自动检测到的本机 HTTP/混合代理地址，或选择已经开启的 TUN；查看实际出口 |
| 4. 准备 Claude Code | 同意后使用 WinGet 安装缺少的 Git/Claude Code；已安装的原生程序会验证版本 |
| 5. token | 输入已有长期 token，或运行官方 `claude setup-token` 授权后输入；输入时不显示字符 |
| 6. 保存与入口 | 生成桌面快捷方式，完成本地配置 |

本包不含订阅、VPS 凭据或 Claude token。线路由提供者另行交付。若线路提供者没有预设出口 IP，向导只显示实际出口，不判断线路是否正确。

## 以后怎样启动

双击桌面 **启动 Claude Code** → 选择项目文件夹 → 进入官方 Claude Code。

首次使用时，在 Claude Code 内确认当前账号、模型及实际请求是否成功。向导保存 token 只代表本地加密成功，不代表服务端鉴权成功。

- **检查 Claude 环境**：检查程序、token 能否由当前 Windows 用户解密，以及当前出口；不发模型请求。
- **重新配置 Claude**：重新走向导；可以选择保留已经保存的 token。
- 直接从其他终端运行 `claude`，不会自动采用这个启动器保存的 token 和代理。

## 如果卡住

- 本机代理地址不确定：打开代理客户端的设置，查 **HTTP 端口 / 混合端口**。不要填 SOCKS 端口。向导不会假定固定端口。
- 选 TUN 后出口不对：检查虚拟网卡是否真正开启、当前节点是否正确。浏览器能联网不能替代终端检测。
- 没有 WinGet：在 Microsoft Store 安装或更新 **应用安装程序**，然后重试。
- WinGet 不支持指定代理：更新应用安装程序；或启用 TUN，退出并重新运行向导，重新选择网络方式。
- 发现已有 `settings.json` 认证/代理字段：向导会保留文件并停止。可以把显示的字段名给维护者处理，不要发送 token 或整个配置文件。
- 无法解密 token：确认使用原 Windows 用户；换电脑或换 Windows 用户后需要重新输入 token。
- 403、登录失败或限流：保留官方 CLI 的具体提示，分别排查账号权限、认证、线路和服务状态；不要直接认定为封号。

失败时可以重试当前步骤或退出后重跑；退出不承诺回滚已经完成的软件安装或 token 保存。

## 数据放在哪里

向导维护的文件位于 `%LOCALAPPDATA%\ClaudeCodeSetup`。token 使用 Windows 当前用户 DPAPI 加密，并限制文件权限；不会写入普通配置 JSON、全局环境变量或分发包。

运行 Claude Code 时需要把 token 解密到进程环境；同用户程序、管理员及 Claude 启动的子工具不构成绝对隔离边界。不要把数据目录当作可公开分享的备份。

配置只应用于本启动器及其子进程。项目、MCP、工具可能有自己的网络行为；当前版本未验证运行中关闭 TUN 的全局阻断，也未独立检查 DNS/WebRTC 泄漏。

此包尚未代码签名。入口使用的执行策略参数只作用于该 PowerShell 进程，不修改系统持久策略；组织安全策略阻止时，请联系管理员，不要关闭系统防护。
